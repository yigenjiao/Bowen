适用场景

源工程找不到了，资产其实还在包里。

很多团队手里只剩打包后的成品：外包只交付了发布包、旧项目的工程已经遗失、要换引擎或做续作。资产并没有消失，只是被压缩、编码、内联封装在包里，常规解包工具打不开。

常见情况

  • 外包只交付了成品包，源工程不在手上
  • 旧项目工程遗失，只剩线上运行的版本
  • 要换引擎、做续作或改版，资产拿不出来
  • 常规解包工具打不开：压缩、编码、内联打包
  • 结论：只能对着截图从头重建

交给我之后

  • 识别引擎、版本与打包方式，选对解码路径
  • 还原网格、UV、骨骼，贴图转为标准图片并绑定材质
  • 场景层级、世界坐标与原始命名原样保留
  • 交付前做包围盒对账与多视角渲染比对
  • 结论：拿到可直接导入 Blender / Unity 的原始资产

输出：GLB + 贴图集 + 节点结构表
交付前的最后一道关

每个模型交付前，都过一遍体检台

这是我把交付时反复手查的项目写成的检查工具，现在免费开放，你也可以拿来查自己的模型。全部在浏览器本地运行，文件不会上传。

TOOL · GLB 体检台

拖进一个 GLB，
查出问题，能修的一键修好

预览模型，同时直接读 glTF 原始字节做体检。每个问题都写了成因和修法，可以一键定位到出问题的网格。法线、权重、骨骼矩阵、多余的 buffer uri 这类有确定答案的问题，勾选后一键修复，生成新文件并自动复查，原文件不动。另有法线、UV 棋盘格、顶点色和骨骼权重视图。

打开体检台 → 看它怎么抓坏样本
  • 坑 1bindposes 行 / 列主序写反
  • 坑 2accessor 按 float64 落盘
  • 坑 3COLOR_0 乘贴图染色 / 发黑
  • 坑 4GLB 的 buffer 带 uri
  • 几何索引越界 · 法线未归一 · min/max
  • 蒙皮权重和 · 骨骼索引越界
  • 场景零缩放节点 · 贴图格式与尺寸
